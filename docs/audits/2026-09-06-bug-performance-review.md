# 软件 Bug 与性能审查（2026-09-06）

本轮审查了交易引擎、模式切换、存档恢复、配置、迁移及绘图热点，并运行现有测试与隔离复现脚本。修改范围是开发规则和审查材料，未修复业务源码。不是全软件无遗漏认证；未运行打包 EXE、真实通达信数据全流程或长时间使用测试。

用户截图作为案例资料：重点提炼前置检查、权限与作用域、状态一致、单个/全部、外部输入和失败反馈；不将其中叙述当作当前软件已有 Bug 的证据。

## 优先处理的问题

### B1 · P1 · 导入的会话可被旧自动保存覆盖（隔离复现）

- 位置：`stock_simulator/app.py:2832`、`:6051`、`:845`、`:2652`。
- 触发：正式训练存在待触发的保存定时器；导入迁移包成功后，在“恢复完成”弹窗仍显示时触发保存。
- 原因：导入完成只设置 `_migration_restore_pending_restart`，关闭事件检查此标志，但 `_persist_session` 不检查且定时器未停止。模态弹窗期间 Qt 仍处理定时器事件。
- 证据：在临时目录导入代码为 `IMPORTED` 的会话，设置导入完成标志，让真实 Qt 保存定时器在事件循环中运行，文件里的代码变回内存旧账户的 `sh600000`。这是确定性调用链复现，未手工操作真实导入弹窗。
- 影响：弹窗表示恢复成功，实际续作数据已被旧数据替换。
- 建议：提交导入前停止并隔离旧保存任务；持久化入口增加导入状态检查；失败时按阶段恢复原保存策略，成功后保持禁止旧写入直到退出。
- 验收：有待执行保存时导入，停留弹窗超过 900 毫秒，验证导入内容不变；另测取消、导入失败和正常退出保存。

### B2 · P1 · 异常配置可阻断启动（隔离复现）

- 位置：`stock_simulator/config.py:141` 的 `sub_pane_indicators` 过滤；调用入口 `app.py:717`。
- 触发：配置为 `{"sub_pane_indicators":[{}]}` 或其中包含列表等不可哈希对象。
- 原因：只验证外层是列表，未验证每项为字符串就用集合成员判断。
- 证据：`load_settings()` 抛出 `TypeError: unhashable type: 'dict'`；窗口初始化直接调用它，没有对应兜底。
- 建议：逐项检查类型后过滤；损坏值回退到默认副图并保留诊断。
- 验收：null、对象、嵌套列表、数字、正常指标混合时仍能打开软件，合法指标保留。

### B3 · P1 · 异常历史成绩容器可阻断启动（隔离复现）

- 位置：`stock_simulator/persistence.py:158` 的 `load_performance_history`；启动调用入口 `app.py:807`。
- 触发：`performance_history.json` 内容为 `{"ordinary_records":null}`。
- 原因：虽然逐条读取带异常处理，但循环之前没有确认记录容器为列表。
- 证据：读取抛出 `TypeError: 'NoneType' object is not iterable`。启动时会加载此历史。
- 建议：区分历史损坏与真正无记录，保留原件并提示恢复路径，不能默认空记录后静默覆盖。
- 验收：容器错类型、坏记录与好记录混合都可控处理，并证明失败不覆盖原件。

### B4 · P1 · 续作文件结构异常可中断恢复（隔离复现）

- 位置：`stock_simulator/persistence.py:39`、`stock_simulator/app.py:6068`。
- 触发：根数据是 `[1]`，或 `{"version":1,"active":null}`。
- 原因：JSON 解析通过后直接使用 `.get()`；恢复入口只捕获行情加载异常，结构解析没有统一边界。后续数字与枚举转换也应一并验证。
- 证据：两种输入分别抛出 list/NoneType 没有 `get` 方法的 `AttributeError`。
- 建议：恢复前完整校验结构，在临时对象中完成转换，全部成功才提交；损坏存档保留供恢复。
- 验收：上述输入和非法枚举均不阻断启动、不留下半恢复状态、不覆盖损坏原件。

### B5 · P2 · 引擎缺少非法价格的最后一道校验（底层复现；界面可达性未证实）

- 位置：`stock_simulator/engine.py:72` 的 `buy_quantity`。
- 触发：直接给引擎开盘价 -10 的数据，买入 100 股。
- 证据：交易返回成功，现金从 10000 变成 10995，持仓增加 100 股。
- 限制：正常会话选择已有部分价格过滤，不能据此声称正常界面可以直接买入负价格。
- 建议：交易引擎验证有限正价格、合法数量、节点和费率，拒绝时账户完全不变；覆盖零、NaN、无穷大与负值。

## 性能改进

### F1 · 优先 · BOLL 每次绘图重复计算完整历史（代码确认并测量）

- 位置：`kline_widget.py:1461`、`:1480`、`:2293`。
- `_calculate_price_range` 和 `_draw_boll_lines` 都调用 `_boll_series`。后者对每根 K 线切片并求均值、方差，绘图过程中至少重复两次。
- 环境：本机 Python 3.10.18，Qt offscreen，合成日期递增数据；默认 BOLL 周期 20；预热一次，再测 9 次单函数调用。

| K 线根数 | 单次中位耗时 | 单次最大耗时 |
| --- | ---: | ---: |
| 1000 | 5.495 ms | 6.334 ms |
| 5000 | 28.667 ms | 31.092 ms |
| 10000 | 58.368 ms | 60.164 ms |

1 万根时仅两次计算约 117 ms，不含其他绘图工作；这是函数测量推算，不是整帧或真实界面帧率测量。实际数据和机器会影响结果。

建议先让单帧共享结果，再按数据、指标参数及行情揭示状态缓存；进一步考虑滚动统计，并验证精度。切换开/收盘、股票、复权、参数后缓存必须正确失效，不能泄露未来数据。

### F2 · 次优先 · 平移图表也重建轮次列表并安排保存（代码确认，未量化）

- 位置：`app.py:5536`、`:5637`、`:5763`、`:6063`。
- 平移调用 `_refresh`，后者清空并重建全部轮次列表；正式训练已开始时还启动保存计时器。保存会序列化所有轮次和权益数据。
- 已有 900 ms 防抖，但它只合并短时间请求，不区分展示变化与账户变化。
- 建议：列表内容没变就复用；仅业务状态变动标记存档待保存。用大量轮次数据测重建耗时和纯平移磁盘写次数后再改。

### F3 · 后续 · GMA、成交量均线仍在绘图路径全量计算（代码确认，未量化）

- 位置：`kline_widget.py:1506`、`:1983`。
- GMA 每次重算 12 组 EMA；成交量均线遍历全历史，即使画面只显示一小段。MA 已有缓存，可参考其复用方向，但不能照搬仅依赖首尾记录的失效条件。
- 建议：指标数据缓存与可见范围绘制分开；先测对应开关打开时的整帧耗时再确定优先级。不要仅凭文件较大就做重构。
